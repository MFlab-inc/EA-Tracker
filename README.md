# Nampin-Tracker

ナンピン型運用の週次確認・四半期確認・ロット段階(フェーズ)管理の記録を、顧客向け説明責任の一環として公開する静的サイト。旧Manus版「AUDCAD 分析ダッシュボード」の後継。

- 公開ページ: GitHub Pages(`index.html`・閲覧専用)
- 記録の追加: `inbox/<ペア>/` のテキストファイルをGitHub上で編集してコミットするだけ(リポジトリ書き込み権限が必要 = 閲覧は誰でも可・記録は権限者のみ、が構造的に保証される)
- バックエンド・APIキーなし。市場データはEA-Risk-Monitorリポジトリが公開するD1履歴(Twelve Data・NYクローズ基準)を読み取り専用で参照

## 記録の付け方(運用者向け)

| 記録 | 編集するファイル | 必須項目 | 自動処理 |
|---|---|---|---|
| 週間確認 | `inbox/<ペア>/weekly.txt` | DD率・記録者(対象週は空欄で自動) | 最大日足pips・100pips超回数を市場データから自動計算 |
| 四半期確認 | `inbox/<ペア>/quarterly.txt` | 四半期・3ヶ月平均ボラ・前月最大ローソク足・記録者 | 平均ボラ80pips境界でモード・ナンピン間隔を自動判定 |
| フェーズ変更 | `inbox/<ペア>/phase.txt` | 変更先フェーズ・変更者・理由 | 現況更新+変更履歴へ追記 |

コミットするとGitHub Actions(`entry.yml`)が起動し、検証→計算→`data/`へ反映→inboxを空テンプレートへリセット、まで自動で行う。同一週・同一四半期の再記入は上書き(冪等)。入力に不備がある場合はActionsが失敗し、inboxは記入内容を保持したまま残る(Actionsログにエラー理由が日本語で出力される)。

## 計算定義

- 週 = 対象週の月曜〜金曜(セッション日付・NYクローズ基準)。土曜の単一価格バーは除外
- 最大日足(pips) = 各日の (高値−安値) ÷ 0.0001 の最大値(小数1位)
- 100pips超回数 = 日足レンジが 100pips を厳密に超えた日数(100.0ちょうどは含めない)
- 対象週の自動判定 = 「金曜のNYクローズが済んだ直近の週」(土曜0:00 UTC以降にその週が対象になる)
- 昇格条件 = ①直近Nローリング週のDD最大値が現フェーズ合格基準以内 ②80pips超イベントが必要回数以上 ③前回変更からNローリング週経過(N・必要回数は `data/<ペア>/phase.json` の current 設定値)

## ペア追加手順

1. `config/pairs.json` にペア定義を追記(pip・モード・フェーズ基準・history_source)
2. `data/<ペア>/` に `weekly.json` / `quarterly.json` / `phase.json` の空スケルトンを作成
3. `inbox/<ペア>/` に `inbox/_templates/` の3ファイルをコピー
4. history_source は EA-Risk-Monitor 側で当該ペアが配信されていることが前提
